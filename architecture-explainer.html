Workroom Mini: Frontend-Backend Architecture

An in-depth visual decomposition of Workroom Mini's educational full-stack design. Engineered with zero frontend frameworks, native ES modules, lightweight revision-based multi-user synchronization, modular Python Flask REST blueprints, and a transactional SQLite data access layer.

Vanilla ES Modules (Zero Build) Python Flask + Werkzeug SQLite 3 + PRAGMA Foreign Keys Atomic Revision Polling (5s) 2D Spatial Pan/Zoom & SVG Cubic Béziers

01. Complete System Topology & Tier Boundaries

Three distinct architectural tiers: the client browser executing native ES modules with a single canonical state store, the Python Flask application delegating to modular domain Blueprints, and the SQLite persistence layer with atomic revision increments.

02. Multi-User Revision Polling & Conflict Prevention

Workroom Mini avoids WebSocket server complexity by using an ultra-lightweight HTTP revision polling protocol. Every mutating database write increments an atomic integer counter on the project row. Peer clients poll this 1-integer endpoint every 5 seconds, employing draft snapshots and gesture guards to never overwrite in-progress user actions.

03. Spatial Canvas 2D Transform & SVG Edge Pipeline

Workroom Mini features an infinite 2D spatial canvas with camera pan/zoom, interactive node dragging, dynamic surface expansion, directed task dependencies drawn via SVG cubic Bézier curves, and a live interactive minimap.

04. Architectural Modules & Design Decisions

Detailed analysis of the 6 pillars powering Workroom Mini's separation of concerns, data integrity, and user experience.

Frontend Architecture /js/workroom/

Vanilla ES Modules & Canonical State

Built without bundlers, Webpack, Babel, or heavy client frameworks. Native ES Modules deliver instant loading with zero compilation overhead.

  • core.js: Houses the single source of truth (state tree), HTTP client (api), toast notifications, and modal lifecycle manager.
  • main.js: Bootstraps application lifecycle (initApp), validates session profile (/api/me), and wires decoupled hooks without circular imports.
  • task.js: Handles Kanban board HTML5 Drag-and-Drop, List view sorting, and the Task Detail Modal with real-time comment threads.
  • project.js: Powers project switching, member collaboration roster, join code regeneration, CSV/JSON exports, and dashboard metrics.
Backend Architecture /backend/

Flask Domain Blueprints & Auth

Clean separation of server responsibilities into domain-driven Blueprints, preventing monolithic route sprawl.

  • server.py: Root app factory configuring secure sessions (HttpOnly, SameSite=Lax), static routing, and Werkzeug scrypt auth (/api/signup, /api/login).
  • backend/common.py: The @login_required decorator guarantees session validity and verifies user existence in SQLite on every protected request.
  • backend/project_api.py: Manages project CRUD, join code validation, member removal, dashboard rollups, and UTF-8 BOM CSV exports.
  • backend/task_api.py: Enforces task CRUD validation, assignee roster verification, and task discussion comments.
  • backend/canvas_api.py: Transactional batch position upserts and directed task dependency graph persistence.
Persistence & DAL database.py

SQLite DAL & Atomic Revision Pattern

A dedicated Data Access Layer using raw SQL. No ORM abstraction layer to ensure complete query transparency and optimal performance.

  • Foreign Key Cascades: Enforces PRAGMA foreign_keys = ON; so deleting a project instantly cascades to tasks, comments, positions, and dependencies.
  • Safe Startup Migrations: Inspects schema columns via PRAGMA table_info on launch, running non-destructive ALTER TABLE when needed.
  • Atomic Revision Counter: Every data mutation increments projects.revision by 1 inside the same database transaction. This powers 1-integer O(1) polling checks!
  • 7 Core Tables: users, projects, project_members, tasks, task_comments, task_canvas_positions, task_dependencies.
Real-Time Sync /js/workroom/sync.js

Zero-Overhead Polling & Draft Guard

Solves multi-user collaboration without the operational complexity of stateful WebSockets or external message brokers.

5-Second Polling Loop
Uses chained setTimeout instead of setInterval to guarantee requests never overlap on high-latency networks.
Gesture Guard
Defers DOM re-renders if sync.isDragging, canvas.isPanning, or canvas.isConnecting is active.
Draft Protection
Compares active modal inputs against taskModalSnapshot; defers background refresh if the user is typing.
Tab Visibility Aware
Listens to document.visibilityState and halts polling when the tab is hidden, eliminating battery and server drain.
Spatial Math /js/workroom/canvas.js

2D Camera Matrix & SVG Bézier DAG

Enables an expansive spatial layout with fluid interactions, coordinate math, and dynamic graph edges.

  • Focal Zoom Math: Wheel zooming anchors to the cursor's world coordinate, updating panX and panY so points under the cursor remain stationary.
  • Cubic Bézier Curves: Evaluates socket handles on predecessor and successor nodes, rendering paths with d="M x1 y1 C cx1 cy1, cx2 cy2, x2 y2".
  • Interactive Minimap: Computes aspect-ratio letterboxing, projects all task positions as color-coded dots, and renders a draggable camera frustum box.
  • Auto-placement: Tasks without positions are automatically placed in a clean grid and batch-saved to SQLite via PUT /api/.../canvas-positions.
Security Baseline Authorization & Access

IDOR Prevention & Multi-Tier Roles

Comprehensive defense-in-depth security model protecting every API route and database query.

  • Triple-Tier Roles: Explicit distinction between Owner (can rename, delete project, manage members), Member (can edit tasks, comments, canvas), and Outsider (403/404).
  • IDOR Prevention: Every task mutation checks that the task belongs to a project the session user is authorized to access.
  • Member Removal Cleanup: Removing a member automatically updates any assigned tasks to assignee_id = NULL, preventing orphaned references.
  • Header Injection Protection: Project CSV export slugs are sanitized using regex to prevent directory traversal and header injection in Content-Disposition.

Detailed breakdown of all API endpoints across Authentication, Project, Task, and Spatial Canvas domains.

POST /api/login server.py Public No Verifies password hash; issues secure HttpOnly session cookie.
POST /api/logout server.py Authenticated No Clears active session cookie.

PATCH /api/projects/:id project_api.py Owner Only Yes (+1) Renames project; increments project revision.
DELETE /api/projects/:id project_api.py Owner Only N/A (Cascade) Deletes project and cascades deletion to all tasks, comments, and positions.
GET /api/projects/:id/revision project_api.py Owner / Member No Lightweight polling heartbeat returning { revision, name, relationship }.
POST /api/projects/join project_api.py @login_required Yes (+1) Adds current user to project via 8-character join code (XXXX-XXXX format).

GET /api/projects/:id/export.json project_api.py Owner / Member No Exports full project snapshot: metadata, tasks, members, canvas, dependencies.
GET /api/projects/:id/tasks task_api.py Owner / Member No Returns all tasks in project with comment counts and assignee usernames.

PATCH /api/tasks/:id task_api.py Owner / Member Yes (+1) Partially updates task title, description, status, due date, or assignee.
DELETE /api/tasks/:id task_api.py Owner / Member Yes (+1) Deletes task and cascades deletion of its comments and canvas positions.
GET /api/tasks/:id/comments task_api.py Owner / Member No Lists all plain-text discussion comments for a task.
POST /api/tasks/:id/comments task_api.py Owner / Member Yes (+1) Adds comment from current user; bumps project revision.
DELETE /api/tasks/:id/comments/:cid task_api.py Author / Owner Yes (+1) Deletes comment; bumps project revision.
GET /api/projects/:id/canvas-positions canvas_api.py Owner / Member No Fetches saved 2D spatial coordinates (x, y) for project task nodes.
PUT /api/projects/:id/canvas-positions canvas_api.py Owner / Member Yes (+1) Batch upserts task coordinates in a single transactional write.
GET /api/projects/:id/dependencies canvas_api.py Owner / Member No Lists all directed task dependencies (from_task_id -> to_task_id).
POST /api/projects/:id/dependencies canvas_api.py Owner / Member Yes (+1) Creates directed edge; validates no self-links, no duplicates, and same project.
DELETE /api/projects/:id/dependencies canvas_api.py Owner / Member Yes (+1) Removes directed dependency edge; bumps project revision.
